# Layout and file template

Part of the [contributor guide](../../CONTRIBUTING.md).

## 1. Folders and layers

```
NLAlib/
  ForMathlib/      general facts not about NLAlib's objects, headed upstream;
                   files named after the Mathlib file they would join            (layer −1)
  Computation/     programs over memory buffers: syntax, runs, counts, memory,
                   substitution, kernel calls, arithmetic models, BLAS kernels,
                   oracle implementations                                         (layer 0)
  Matrix/          deterministic matrix analysis                                  (layer 0)
  Polynomial/      scalar approximation theory and the function classes it
                   approximates                                                   (layer 0)
  Krylov/          deterministic Krylov theory                                      (layer 1)
  Probability/     scalar and vector probability, concentration                  (layer 1.5)
  RandomMatrix/    Gaussian, sub-Gaussian, Haar random matrices                     (layer 2)
  Sketching/       sketch distributions and their embedding guarantees             (layer 3)
  Regression/      randomized least squares and linear-system solvers
                   (sketch-and-solve, sketch-and-precondition, iterative
                   sketching, Kaczmarz, sketch-and-project)                      (layer 3.5)
  LowRank/         low-rank approximation                                          (layer 4)
  Estimation/      trace and spectral-density estimation                         (layer 4.5)
  LowerBounds/     lower bounds for randomized algorithms and named estimators,
                   one subfolder per topic (LowRank/, ...); may import every
                   other folder, and only LowerBounds imports it                  (layer 5)
NLAlibTools/       tools, not library: the Float interpreter, the NumPy emitter, examples
docs/              references.bib, constants.toml (named bounds), targets.toml and targets.approved
                   (the target registry, programs.md), rules/ (rule data, generated digest),
                   contributing/ (these guides), design/ (design notes),
                   renames/ (rename maps, naming.md N12)
scripts/           the checks (checks.md): stage_check.sh, Audit.lean, Replay.lean, Lint.lean,
                   Programs.lean, Targets.lean, check_rules.py, check_refs.py, ..., and their tests
```

The subdirectories of each layer are decided in that layer's design note ([design](design.md)), not in advance.

**Imports.** A module imports only modules of its own layer number or lower [P1].
`docs/rules/layers.toml` holds the same numbers, one entry per top-level folder; a folder missing
from it is a P1 error, so a new folder gets its entry before it gets files. Folders with the same
number (Computation, Matrix and Polynomial, all 0) may import one another, except where an entry
narrows its imports (below). A half layer sits between two whole ones:
Probability may import Krylov and Krylov may not import Probability; likewise Regression above
Sketching and Estimation above LowRank. LowerBounds, the top layer, combines the others, with one
subfolder per topic; a lemma a lower bound needs that is not itself a lower bound stays in its
topic folder. A topic goes where its statements are about (randomized linear-system solvers such
as Kaczmarz are in Regression); finding results by task is the explorer's job.
`python3 scripts/check_rules.py --files <files>` checks the import rules of the files you changed
in seconds.

A folder may import less than its number allows: its `layers.toml` entry lists the only folders
it may import, the rule that checks it and the reason. ForMathlib imports nothing else in NLAlib
[P1]; a file in `NLAlib/Computation` imports only Mathlib, `NLAlib.ForMathlib` and
`NLAlib.Computation` [E5], so that a program over the library's objects lives in its topic file;
a file in `NLAlib/Polynomial` imports only Mathlib, `NLAlib.ForMathlib` and `NLAlib.Polynomial`
[P11], so that the layer can go upstream to Mathlib as a whole, and while P11 holds the layer
keeps its headline scalar results and is exempt from P9.

The root file `NLAlib.lean` is generated by `lake exe mk_all --module --lib NLAlib`; CI checks it
is current. There are no per-directory aggregator files: a user imports the file they need [P2].

**ForMathlib.** `ForMathlib` holds the general facts about none of NLAlib's objects: a scalar
inequality, a real-analysis or measure-theory lemma with no matrix or measure in its statement
[P9]. Its statements use no NLAlib vocabulary [P4]. They are declared in the Mathlib namespace
they would have upstream [P5], marked in the module docstring as upstream candidates [P6], in a
file named after the Mathlib file they would join [P7], and deleted when they land in Mathlib.
A topic file keeps every statement about NLAlib's objects and every statement in Mathlib's matrix
or probability vocabulary whose subject is a Mathlib hypothesis structure
(`theorem _root_.Matrix.PosSemidef.foo`, §2); any other declaration outside `NLAlib` belongs in
ForMathlib [P8].

**Exceptions are data.** What applies to one folder lives in data files, each entry with its
reason: its layer and import limits in `docs/rules/layers.toml`; a rule it is exempt from in that
rule's `exempt` field of `docs/rules/rules.toml` (with `exempt_while` for a condition and
`exempt_reason`, as for Polynomial and P9 above); a single declaration or file excused from a rule
in `scripts/rules_allow.toml` or `scripts/names_allow.toml` ([naming](naming.md) §5,
[checks](checks.md) §1). The generated `NLAlib/<Topic>/RULES.md` shows all of them for its
folder, under "This topic". The guides state the rules; they do not list the exceptions, so a new
topic or a new exception is a data entry, not a change to the prose.

## 2. File template

Every file has this shape. The header linter checks the first lines; the module system is the
one Mathlib uses.

```lean
/-
Copyright (c) 2026 NLAlib contributors. All rights reserved.
Released under Apache 2.0 license as described in the file LICENSE.
Authors: NLAlib contributors
-/
module

public import Mathlib.Analysis.Matrix.Spectrum
public import NLAlib.Matrix.Norms.Spectral

/-!
# Weyl's inequalities

Perturbation bounds for the eigenvalues of Hermitian matrices and the singular values of
arbitrary matrices.

## Main results

* `Matrix.IsHermitian.eigenvalue_add_le`: Weyl's inequality `λ_{i+j}(A + B) ≤ λ_i(A) + λ_j(B)`.
* `NLAlib.singularValues_add_le`: the singular-value form.
-/

@[expose] public section

open scoped Matrix MatrixOrder

namespace NLAlib

variable {𝕜 : Type*} [RCLike 𝕜] {m n : Type*} [Fintype m] [Fintype n]

...

end NLAlib
```

Rules:

- The header linter requires a non-empty `Authors:` line [F1]; use `NLAlib contributors` unless
  the file keeps the attribution of material taken from elsewhere.
- `module`, then `public import` lines (specific Mathlib files; never `import Mathlib` or
  `import Mathlib.Tactic` [F3]), then the module docstring, then `@[expose] public section` [F2].
- Everything is in `namespace NLAlib` [F4], except lemmas whose subject is a Mathlib structure
  hypothesis (`Matrix.IsHermitian`, `Matrix.PosSemidef`), which are declared
  `theorem _root_.Matrix.IsHermitian.foo` inside `namespace NLAlib` so that `hA.foo` works [P8].
- No file-level `set_option` [F5] (`maxHeartbeats`, `backward.*`, a linter), `open Classical` or
  `open scoped Classical` [F7]. A single declaration that needs a heartbeat bump gets
  `set_option maxHeartbeats N in` on that declaration, with a comment saying why [F6].
- `private` for proof-local helpers only. A lemma a second file could want is public, named by [naming](naming.md),
  documented by [docstrings](docstrings.md), and placed in the file that owns its subject, not the file that needed it
  first (review list: [S5]).
- `noncomputable section` is not opened at file level [F8]; mark individual definitions
  `noncomputable` when Lean requires it.
- Lines are at most 100 characters [S7]. Only a line that one identifier or a URL makes long may
  be longer (a declaration name on its own line, a backticked name in a docstring), under
  `set_option linter.style.longLine false in` on that declaration with a comment saying why, and
  only where a line needs it [S8]. CI builds with `--wfail`, so the
  Mathlib linters (header, long lines, `open Classical`, `set_option`) fail the build.
